# CLAUDE.md

This file guide Claude Code (claude.ai/code) for work in this repo.

Amazon PPC audit + profit console. Upload Amazon exports → flags, bid plans, profit P&L, keyword research, exec reports. FastAPI + SQLAlchemy + pandas backend, React (Vite) + Tailwind frontend. 100% local, no Amazon Ads API — every "action" = downloadable bulk `.xlsx` user re-uploads to Amazon.

## Authentication

**Per-user data isolation:** each store dir namespaced by owner numeric user id — internal id `u<id>__<store>`, public id (API/UI) un-prefixed slug. `database.scoped(user.id, store)` translates at boundary: `get_db` namespaces transparently (every `Depends(get_db)` router per-user isolated, zero code), `stores` router scopes list/create/delete via `list_stores(user.id)` / `scoped()`. New users auto-get isolated `zvalves`/"My Store". User ids never reuse (`sqlite_autoincrement`); `delete_user` purges owner store dirs, so recycled id can't inherit stale data. Bundled seed in **SAdmin** namespace.

`auth.py` = **central** auth store (`data/auth.db`, own engine/Base — separate from per-store/project pipeline DBs). Username/password, stdlib PBKDF2 hashing (`pbkdf2_sha256$iters$salt$hash`, no native dep). Login mints opaque bearer token stored server-side (`sessions` table), sliding 12h expiry; **one active session per user** (new login revokes prior sessions). Superuser **SAdmin / RootPass** seeded on startup (`init_auth()`, override via `SUPERUSER_NAME`/`SUPERUSER_PASS` env). `routers/auth.py` = `/auth/login|logout|me`, public `/auth/register` (self-signup → normal user + auto-login, no email/OTP, min 6-char password), + superuser-only user CRUD (`/auth/users…`). In `main.py` every data router gated `dependencies=[Depends(auth.current_user)]`; only `/auth/*` + `/health` public. Frontend: `api/client.js` keeps token in `localStorage`, attaches `Authorization: Bearer` to every request via `authFetch`, on any 401 clears it + fires `ppc-unauthorized`; `App.jsx` gates whole UI behind `Login.jsx`, superusers get **Users** tab (`Users.jsx`). Scales 1000+ users (indexed rows; swap SQLite→Postgres by URL).

## Multi-tenant data model (the core thing to understand)

Data isolated **per store → per audit (project) → per Audit Cadence** as separate SQLite files: `backend/data/stores/<store_id>/<project_id>[__<cadence>].db`. Campaign IDs from different Amazon accounts never collide — files physically separate.

**Per-cadence isolation (third level):** each Audit Cadence (`daily`/`weekly`/`mid_month`/`pause_scale`) gets **own db file** `<project>__<cadence>.db`; `full_month` (and no cadence) map to **base** `<project>.db` (back-compat: existing data = Full-Month set). So PPC bulk uploaded under Weekly **only** audits Weekly — its campaigns/ads/targets/flags/bid-opt/placement/harvest/n-gram/negatives never overlap another cadence. Needed **zero pipeline changes**: `get_db` folds cadence into db path (`_data_pid`), so every `Depends(get_db)` router isolates per cadence automatically, like per-user namespacing did for stores. Shared across all cadences of a project (so no re-enter per cadence): **Goal ACoS + econ** (`_meta.json`, keyed by *base* project), **Product Benchmark** (`_benchmark.json`), **Product Costs** (`_costs.json`, store-level — `get_store_costs`/`set_store_costs`; `benchmark.cost_map` reads it so `profit.compute` works in any cadence session without cross-db join). **Monitoring** (daily-report tracker) uses `get_base_db` (always base file, cadence-agnostic). `CADENCE_KEYS` in `database.py` hardcoded (no import of `pipeline.cadence`, avoids cycle).

- `database.py` = spine. `get_db()` / `get_session()` read `?store=&project=` **query params**, return session for that file. FastAPI dependency → **every pipeline router auto-scoped, zero per-router code** — new routers just `Depends(get_db)`.
- Session carries `(store, project)` in `session.info` (+ `cadence`/`data_project`) so pipelines reach store-scoped resources without extra params (e.g. store-wide benchmark + costs). `get_db` also reads `?audit_type=` (cadence), scopes db file to it; `get_base_db` same dependency but pinned to base file (shared cross-cadence features like Monitoring). `pinned_db(cadence)` = factory pinning a router to ONE cadence, ignoring ambient `?audit_type=` — the five cadence routers (`dailywatch`/`weekly`/`midmonth`/`fullmonth`/`pausescale`) use it (their URL path IS the cadence), so keep-alive cadence panels fetching in background always hit own db file.
- Engines cached lazily in `_engines`; `slug()` sanitizes ids (blocks path traversal). `delete_store`/`delete_project` dispose engines before removing files. Delete from UI **switches selection away first** so in-flight request doesn't re-create file via `get_db` auto-create.
- Titles + per-audit settings (Goal ACoS, refund/referral/COGS %) live in `<store>/_meta.json`. **Store-wide Product Benchmark** lives in `<store>/_benchmark.json` (upload once, every audit matches against it). Generic KV helpers: `get_store_extra`/`set_store_extra` (store `_meta.json` keys — brand terms, upload-meta "last uploaded file") + `get_project_extra`/`set_project_extra` (per-project keys — waterfall settings). New store-level JSON: `_catalog.json` (product catalog), `_transactions.json` (SKU transaction ledger), `_fba.json` (base fulfillment fee + referral fee per unit from the **Selling economics (SKU Economics)** report or FBA Fee Preview — `pipeline/fbafees.py`, one loose-column parser for all; ALL sheets of a workbook parsed, so a **Referral Fee Preview** sheet/file yields `kind="referral"` rows that `merge()` applies over the matching item's referral fee (by SKU else ASIN, `%`-only rows priced off the item price) and recomputes `total_fee` (highest rate wins when several preview SKUs hit one ASIN-keyed item); `be_metrics.total_source` = `report` (exact quoted total) / `scaled` (report fees, referral re-priced at the listing's price — a fixed $ referral is wrong at another price) / `derived`; rows key by SKU else ASIN since Selling economics leaves MSKU empty. Both fees win over ledger-observed values in `catalog.fees_by_sku` (report = current base fee + marginal referral rate; ledger = refund-netted average), and their sum `total_fee` is charged by `benchmark._unit_economics` as the exact per-unit Amazon fee (`BE = (price − COGS − total_fee) ÷ price`) instead of re-deriving referral as % of price. Mapped to CHILD/standalone ASINs only — `Parent ASIN` never a key — and feeds `benchmark.cost_map`) — deleted with store dir.
- Frontend mirrors this: `api/client.js` holds module-global `STORE`/`PROJECT`/`CADENCE`; `q()` injects `?store=&project=&audit_type=` into every call. `App` calls `api.setCadence()` **synchronously** when cadence picked (before child panels refetch), per-cadence panels carry `auditType` in `scope` prop so they refetch on cadence switch.

## Schema + metric rules

Star schema in `models.py`: dimensions (`DimProduct/Campaign/AdGroup/Ad/Target`) + `FactPerformance` (raw metrics stamped `snapshot_date` — every upload = snapshot). Side tables: `FactSales`, `FactDaily` (one row/day for Monitoring tracker, upserted by `date`), `FactPlacement`, `ProductBenchmark`, `MinedKeyword`, `ChangeLog`, `ChecklistItem`. Several features keep **own** tables, deliberately separate from star schema, so each runs off own dedicated upload, never shifts audit snapshot: `DailyWatchFact`, `WeeklyTermFact`, `MidMonthTermFact`, `FullMonthTermFact`, `PauseScaleTermFact` (cadence panels) + `ProductAdFact` (Product Ads tab) + `WaterfallRun`/`WaterfallItem`, `BidLedger`, `OverlapFinding`, `SPChannelFact`/`SBFact`/`SDFact` (account-level engines, below) + `TrackerProject`/`TrackedCompetitor`/`TrackedKeyword`/`RankSnapshot`/`KeywordUsage`/`ListingCopy`/`BannedKeyword` (Listing Optimizer). (Product **costs** no longer DB table — live in store-level `_costs.json` so shared across cadences; `ProductCost` model still exists but unused by pipeline.)

- **Never store derived rates.** ACoS/CTR/CVR/ROAS/break-even/profit computed in `metrics.py` / pipeline modules from raw counts. Bid math (`target_cpc_bid`, `target_acos_bid`) also in `metrics.py`.
- **FKs use `ON DELETE CASCADE`**, SQLite FK enforcement ON (per-connection pragma in `database.py`). Loader sets `PRAGMA defer_foreign_keys=ON` so dims insert in any order.

## Point-in-time consistency (easy to get wrong)

Multiple uploads accumulate snapshots. "Current period" views must use **latest** snapshot, never sum lifetime:
- `audit.active_snapshot(db)` = latest `FactPerformance` date. `audit()`, `build_tree()`, `sales._ppc_by_asin()`, `profit.compute()`, `sales_view()` all default to it.
- `build_tree` (hot path — Python loop over all dims+facts) **cached** per `(db url, snapshot, max perf_id)`; invalidates automatically when fact rows change.
- **Account ad cost = Σ Spend of `Entity=campaign` rows** (`sales.total_ad`), NOT ASIN rollup — rollup double-counts campaigns advertising multiple ASINs. Use for account ACoS/TACoS/profit.

## Pipeline + flag engine

`pipeline/` staged: `ingest → split → clean → load`, then `audit`. Side pipelines: `harvest`, `ngrams`, `trends`, `sales`, `profit`, `benchmark`, `bidopt`, `placement`, `strategy`, `keywords`, `report`, `checklist`, `changelog`, `monitoring`, `cadence`, `dailywatch`, `weekly`, `midmonth`, `fullmonth`, `pausescale`, `productads`, `cadstrat`, `ml`, plus account-level `waterfall`, `cannibal`, `channels`, `ledger` and store-level `catalog`, `transactions`, `tracker` (own sections below).

`ml.py` = **NumPy-only ML for the cadences** (no new deps, no persistence, no RNG — deterministic per plan). Empirical-Bayes Beta-binomial CVR shrinkage (`fit_beta_prior`/`posterior`/`p_below`, own `betainc` continued-fraction so no scipy) fixes thin-data CVR; `robust_anomalies` (median/MAD z-score) for Daily Watch; `holt_forecast` (double exponential smoothing) for Weekly's next-week projection; `LogReg`/`train_term_model`/`score_terms` (hand-rolled logistic regression, quality-gated on AUC) for Full Month's Early Promote Candidates. `enrich_plan(plan, agg_rows, target_acos)` is the integrator every cadence calls at the end of its `plan()` (`weekly.py`/`midmonth.py`/`fullmonth.py`/`pausescale.py`): stamps each bid_tweaks/promotes/negates/bleeders/scales/pauses row with `row["ml"]` (smoothed CVR + confidence) and sets `plan["ml"]` (prior + break-even CVR, `None` when the account's too small — every model degrades silently, never fabricates). Advisory only — never changes exported bulk bids. Frontend: `components/MLInsights.jsx` (per-cadence card) + `mlCols`/`withML()` in `components/cadenceCols.jsx`. `cadence.py` holds **audit-type presets** (Daily/Weekly/Mid-Month/Full-Month/Pause-Scale): each sets lookback label + `Thresholds` overrides that re-tune flag engine (passed via `audit_type` to `/audit`, `/asins`, `/dashboard` → `cadence.thresholds_for`) + SOP effort checklist + **`focus`** flag set + `feature`/`table_title` (in `list_presets()`) so each cadence renders **own distinct, bulk-derived table** (its unique feature) instead of same flag list. Frontend `AuditTable` scopes to active cadence `focus` (`[]` = all flags = Full Month): weekly = `HIGH_ACOS`+`OVERBID` (bid tweaks), mid_month = `WASTED_SPEND`+`HIGH_ACOS`+`LOW_CTR` (negatives & bid adjust), pause_scale = `BLEEDING`+`WASTED_SPEND`+`SCALE_WINNER` (pause/kill/scale). `daily` preset = `feature:"watch"` — not flag-based; its table hidden, Daily Watch spike tracker (own `DailyWatchFact` time series) shows instead. `weekly` preset = `feature:"weekly"`, `mid_month` = `feature:"mid_month"` — flag tables likewise hidden for dedicated panels (`weekly.py` / `midmonth.py`, below); App gates on `!['watch','weekly','mid_month'].includes(feature)`. Runs persist per (year, month, audit_type) in `CadenceRun`/`CadenceTask` (month = label on latest snapshot, not data filter). `dailywatch.py` powers **Daily Watch** cadence day-over-day anomaly tracker (`/daily-watch/upload|days|compare|series`). Keeps **own table `DailyWatchFact`** (one row per campaign per day, upserted by `(date, campaign_id)`), **deliberately separate from `FactPerformance`** so daily spike-tracking never shifts audit's "latest snapshot" Weekly/Mid/Full/Pause cadences read — those four share one monthly bulk snapshot; Daily Watch independent time series. Each upload parses bulk campaign rows (`ingest→split→clean`, then reads `frames["campaign"]` directly — **not** `load.load`), replaces that day. `compare(prev, cur)` diffs account + per-campaign rows for spike flags (spend spike, ACoS spike, sales drop, zero-order spend), `series` returns accumulated daily totals for trend chart. Watch-only — emits no bulk file. Rendered inside `AuditCadence.jsx` when Daily Watch selected (`DailyWatch.jsx`). `weekly.py` powers **Weekly Optimization** cadence (`/weekly/upload|weeks|series|plan|bulk`), **Sponsored Products only**, driven straight from bulk **SP Search Term Report** sheet (not `load.load`) — keeps **own table `WeeklyTermFact`** (one row per STR line, carrying report real Campaign/Ad Group/Keyword/Product Targeting IDs as exact strings), **separate from `FactPerformance`** so Weekly bulk only drives Weekly cadence. Mirrors Daily Watch calendar grid but panels = **weeks** (`WeeklyTermFact.week`, Week 1..N, min 5): each week panel uploads own bulk (upsert per week — replaces just that week), weeks accumulate into `series()` trend, `plan(db, t, week)` scopes bid-tweaks + harvest to selected week (default = latest via `_resolve_week`). Legacy single-snapshot tables auto-migrate (`_ensure_schema` ALTERs in `week` column, default 1). STR compute model-agnostic (`compute_bid_tweaks(rows,t)` / `compute_harvest(rows,t,min_orders,bleeder_acos_mult)` / `summarize(rows)` / `to_bulk` / `parse_str_sheet` / `compare_rows(prev_rows,cur_rows,target_acos)` → account deltas + per-campaign movers + spike flags) so other cadences reuse on own tables. `weekly.compare(db,prev_week,cur_week)` = week-over-week (`/weekly/compare`); week delete via `/weekly/week`. Single-snapshot history helpers (`ensure_period_col`/`shift_and_insert`/`period_rows`/`has_previous`) keep a `period` col (0=current, 1=previous) so Mid/Full compare current upload vs previous. `midmonth.py` = **Mid-Month Check** cadence (`/mid-month/upload|plan|bulk`): **single-panel** (own table `MidMonthTermFact`, one snapshot, replaced per upload), focused on **bid adjustments + heavy negative targeting** — calls shared Weekly engine with `bleeder_acos_mult=2.0` so `compute_harvest` returns third list, **bleeders** (converted but ACoS ≥ 2× goal), alongside `negates` (0-order wasted). Bleeders pre-filtered to act-worthy: `bleeder_min_orders=2` (one order ACoS = noise) + spend ≥ `bleeder_spend_mult`(2.0)×loser-floor (head $-bleeders only). Rendered as `MidMonth.jsx` (bid-adjust table + wasted-negatives + bleeders, bleeders not pre-selected — negating them stops sales). On each upload shifts prior snapshot to `period=1` so **Compare to previous** (`/mid-month/compare` → `compare_rows`) works; plan reads only `period=0`. `fullmonth.py` = **Full Month Audit** cadence (`/full-month/upload|plan|bulk`, own table `FullMonthTermFact` in base db): **superset** — calls shared engine to return `bid_tweaks` + `promotes` + `negates` + `bleeders` all at once (full 30-day thresholds). Rendered as `FullMonth.jsx`. Same previous-upload history as Mid-Month → **Compare to previous** (`/full-month/compare`). `pausescale.py` = **Pause/Scale Audit** cadence (`/pause-scale/upload|plan|bulk`, own table `PauseScaleTermFact`): unlike others acts on **existing entities** (not customer search terms) — calls shared `weekly.aggregate_targets(rows)`, returns `scales` (10+ orders ≤ goal → bid up via `target_cpc_bid`), `pauses` (30+ clicks, 0 orders → state=paused), `campaign_pauses` ($50+ spend, 0 orders → pause whole campaign). Own `to_bulk` emits Keyword/Product Targeting *update* (bid or state=paused) + Campaign *update* (state=paused), all by exact ID; logged via `changelog.from_pausescale`. Rendered as `PauseScale.jsx` (scale / pause-target / pause-campaign tables, campaign pauses not pre-selected). **All five** cadences now hide generic flag table for dedicated panels (App gate `!['watch','weekly','mid_month','full_month','pause_scale'].includes(feature)`). Richer generic optimization panels (BidOptimizer/Placement/AsinTree/Harvest/Ngram) still render below for every non-watch cadence. `bid_tweaks` aggregates each existing keyword/product-target, recomputes bid (`M.target_cpc_bid` + `bid_optimizer` guardrails: step cap, hard caps, no thin-data raise), updates **by ID**. `harvest` aggregates each customer search term in its ad group → winners (orders ≤ goal ACoS) promote to Exact keyword / product target, losers ($ spend, 0 orders) negate — same Amazon-safety rules as `harvest.py` (ASIN↔keyword separation, no kw+pt mix per ad group, no auto-clause promote, in-file dedup). `to_bulk` emits chosen bid updates + creates + negatives as one validated SP bulk; `changelog.from_weekly` logs them. Rendered as `WeeklyOptimization.jsx` inside `AuditCadence.jsx` when Weekly selected; generic flag `AuditTable` hidden for it (App gate on `feature !== 'weekly'`). `productads.py` = **Product Ads** tab — **own dedicated bulk upload + own table `ProductAdFact`**, fully separate from audit star schema. `parse_product_ads(path)` reads bulk Sponsored Products Campaigns sheet, keeps only `Entity='Product Ad'` rows (ASIN/SKU + real IDs as exact strings + metrics); `ingest` replaces snapshot. `summary` consolidates one row per (ASIN, SKU) with status (no_data/no_orders/ok) + account total; `detail(asins)` drills into ads + per-campaign rollups — all from `ProductAdFact`, no audit flags/strategy. Routes `/product-ads/upload|<base>|detail`. Frontend `ProductAds.jsx` has own Upload-bulk button + empty state. `GET /stores/overview` rolls up KPIs (ad spend/sales/ACoS/ASINs/flags) across all user stores for Stores tab. `monitoring.py` consolidates daily **Business Report** + **Sponsored Products** report by date into `FactDaily` (idempotent upsert), `summary(db, start, end)` computes Daily SALES & PPC Tracker features (day-over-day deltas, 7d rolling, CVR-fall / buy-box / refund-spike / ASP-swing alerts, traffic-vs-CVR divergence, weekday/weekend, B2B split, 0-100 health score) over range — missing calendar days come back null → UI renders "-". Percent fields stored as plain number (24.03, not 0.2403). Frontend Monitoring tab (`Monitoring.jsx`) renders with **Chart.js** (`chart.js` + `react-chartjs-2`, app only chart deps). `cadstrat.py` = **per-cadence Strategy Advisor**: Weekly/Mid-Month/Full-Month/Pause-Scale each drive own strategies from own side-table data via that cadence's plan pipeline (NOT star-schema `FactPerformance` the generic `strategy.analyze` reads); output shape matches generic advisor (`{recommendations, playbook, counts}`) so Strategy panel renders identically, each named strategy emits its cadence's bulk. `GET /strategy?audit_type=` routes to `cadstrat.analyze` for those four types (`cadstrat.CADENCE_TYPES`), else generic advisor.

- Flag rules pure `(metrics, thresholds, ctx) -> Flag|None` in `rules.py`, registered in `TARGET_RULES`. Add rule = add function + list entry. `audit.py` injects per-target context (over-goal history for reduce→monitor→pause **bid ladder**, per-ASIN break-even, per-ASIN goal override).
- Any engine emitting Amazon bulk file (`automate`, `bidopt`, `placement`, `harvest`, `strategy`) logs actions to `ChangeLog`, routes output through `bulkfmt.py` so file passes Amazon validation: ASIN search terms become `asin="B0..."` (negative) **product targets** (never keywords); auto-campaign clauses (loose/close-match, substitutes, complements) can't be negated → skipped; keyword text checked with `bulkfmt.valid_keyword` (≤80 chars, ≤10 words, no control/￼/special chars) or dropped ("Keyword is invalid"); IDs emitted via `bulkfmt.idstr` as exact integer strings; target repeated in-file (update **or** create/negate) or already in account dropped (no "Duplicate Id"/"Duplicate Keyword Text"/"already exists"). To know what already exists, `load.py` stores existing **Negative Keyword / Negative Product Targeting** rows as `DimTarget` (`target_type` `negative_keyword`/`negative_product_target`); `harvest` also tracks existing **positive** keyword + product-target expressions per ad group. These negatives carry no facts, excluded from `audit`/`bidopt`/`build_tree` (key off positive types + fact rows). Existing data must be **re-uploaded** once for account-dedup to apply.
- **Amazon entity IDs = 16-18 digits — past float64 exact range.** `ingest` reads every `* ID` column as **string** (`dtype=str`); `clean._idstr` keeps exact. Reading as numbers mangles big IDs (`…929` → `…929.0`/`.9`), Amazon rejects as "temporary ID" or collides two IDs into "Duplicate Id". Never let ID become float.
- View **ASIN-rooted**: storage campaign-rooted; `build_tree` re-roots at query time by walking ad → ad_group → campaign, grouping by ad ASIN. Campaign/ad-group metrics = whole campaign (shared up under each ASIN) — ad/target level exact. `/dashboard` returns **full forest** as `trees` (every ASIN node, ordered by spend) — frontend `AsinTree` renders each ASIN as collapsible row → its campaigns → ad groups → ads + targets. (`tree` = top ASIN only kept for back-compat; don't rely on it for list.)

## Account-level engines (base db, ledger-aware)

Newer engines **account-level**: always base project db via `get_base_db` (cadence-agnostic, like Monitoring), own tables, never touch `FactPerformance`/`active_snapshot`. All IDs exact strings.

- `waterfall.py` = **Waterfall Restructure Engine** (`/waterfall/upload|run|bulk|applied|override|benchmark|settings|ledger`): one uploaded bulk → draft restructure plan into RAF Funnel System (AT discovery → KWT-BROAD → KWT-PHRASE → KWT-EXACT money tier + PT ASIN tier; each downstream promotion = negativeExact upstream; 1 SKU per campaign, boss campaign per SKU+slot, duplicates consolidated). Plan = **4 phased bulks in dependency order**: A renames (zero risk) → B loser bid cuts (transitional overlap, not pause) → C creates (new campaigns born paused + seeds + sculpting negatives) → D pauses (**UI-gated until A–C marked applied**, `/waterfall/applied` enforces order). Own tables `WaterfallRun`/`WaterfallItem`; settings (naming template, budget, seeds, heroes, `bid_floor`/`bid_ceiling`, `force_down_only`, `protect_min_orders`, `protected_campaign_ids`, `slot_bids` per-slot NEW-campaign default bid, `new_strategy` NEW-campaign bidding strategy `down`/`up_down`/`fixed`) via `get_project_extra`. `render_name` placeholders: `{sku}`/`{asin}`/`{slot}`/`{n}` (slot #)/`{bid}`/`{strategy}` (`down`/`up/down`, read from data). NEW campaigns (Phase C): ad group default bid + AT split-target bids scale off `slot_bids` (`DEFAULT_SLOT_BIDS` AT .30/BROAD .50/PHRASE .50/EXACT .50/PT .40; `AT_SPLIT_MULT` close 3.33/loose 2.50/subst 2.50/comp 1.67 — defaults reproduce legacy 1.00/.75/.75/.50), strategy from `STRATEGY_STR[new_strategy]`. **Boss override:** `select_bosses(classified, goal, forced={"sku|slot": campaign_id})` honors user picks; `_boss_map` carries full candidate metrics per group; upload saves raw bulk to `<store_dir>/_waterfall_bulk__<project>.xlsx` (`save_bulk`/`saved_bulk_path`, cleared by `delete_all`) so `POST /waterfall/override` → `rebuild_with_overrides` re-runs the plan (deletes+replaces latest run in place, keeps older day-0 baselines) with no re-upload. Phase D pause protection: `protect_min_orders` guards EMPTY campaigns with orders (flagged in `_pause_warnings.protected_empty`, not auto-paused — losers still pause since sales continue under boss); `protected_campaign_ids` skip B+D. Day-0 hero benchmark vs latest → day-21 verdict. Frontend `Waterfall.jsx` (ASIN×slot grid `WaterfallGrid` + click-to-override `CandidatePanel`, `WarningsCard` pause-wave revenue-at-risk).
- `ledger.py` = **effective-bid ledger** (`BidLedger`, always base db — `base_session(db)` opens from any per-cadence session). Fixes: consecutive exports from same snapshot double-apply bid changes. Every bulk-emitting module `record()`s exported bid/state changes; later bid computations read **effective** value = latest ledger row else snapshot. Row lifecycle: exported (`applied=False`) → user clicks "Mark applied" or new upload shows value landed (auto-reconcile) → or "Discard" deletes. Unapplied rows older than `STALE_DAYS` (7) = warning (`/waterfall/ledger`).
- `cannibal.py` = **Cannibalization / Keyword Ownership Detector** (`/cannibal/run|findings|summary|bulk`, table `OverlapFinding`; findings **regenerated wholesale per run** — idempotent replace). Type 1 = duplicate targets (same keyword_text+match_type or PT expression enabled in 2+ campaigns); Type 2 = cross-product STR overlap (same customer search term converting for 2+ different SKUs; SKU attribution term → source campaign → `waterfall.classify`, MULTI campaigns → 'ALL', reported never auto-resolved). Owner rule (`resolve_owner`, pure): candidates with clicks ≥ min_clicks, max CVR wins, tiebreak min ACoS. 'coexist' verdicts (no action): all candidates profitable + enough clicks, or same-SKU tier pair (waterfall working — only emits missing sculpting negative). **Converter guard:** never emit negative where term itself converts or is live enabled keyword. Shares Waterfall upload (`POST /waterfall/upload?engines=waterfall,cannibal`). Frontend `Cannibalization.jsx`.
- `channels.py` = **Channels** — SB/SD visibility (`/channels/*`, v1 read-only, no SB/SD bulk emit). ## Parsers are tolerant

Amazon/Helium10 exports drift. Parsers (`ingest`, `harvest.parse_str`, `sales.parse_business_report`, `benchmark.parse_benchmark`, `keywords`) accept `.xlsx/.xlsm/.csv`, auto-pick right sheet, **skip metadata-preamble rows to find real header** (Brand Analytics SQP), strip `$`/`%`, handle 7/14-day column drift, convert ROAS↔ACoS. Bulk upload also auto-harvests embedded `SP Search Term Report` sheet if present. Add CSV/format support by matching columns loosely, never by exact header.

**xlsx read engine:** `pipeline/workbook.py` reads via **`calamine`** (Rust, `python-calamine`) when installed — ~8x faster than openpyxl on a big bulk (120k-row SP sheet: ~2.5s vs ~21s; full `ingest.frames` ~3.4s), identical `dtype=str` output so 16-18 digit IDs stay exact. `workbook.excel_engine()` resolves it once at import and **falls back to openpyxl** if absent (optional dep). Every `pd.read_excel`/`pd.ExcelFile` in the parsers passes `engine=workbook.excel_engine()` (`ingest`→`workbook.read_str`, plus `harvest`/`benchmark`/`keywords`/`tracker`/`monitoring`); `catalog`/`transactions`/`fbafees` use openpyxl `read_only=True` streaming (cell-by-cell, already lean). Reads cached by (path,size,mtime) in `workbook` + `ingest` (see caches). **Writes** (bulk emit, 13 `ExcelWriter` sites) stay on openpyxl — small subsets, styled-writer compatible.

## Design system

Binance-style, token-driven so whole app reskins centrally. **Never hardcode hex** — use Tailwind tokens in `tailwind.config.js`: canvas `ink` (#0b0e11), surface `panel` (#1e2329), hairline/elevated `edge` (#2b3139), `mute` (#707a8a), `body` (#eaecef). Single brand accent = Binance Yellow, exposed as `primary`/`lime` (#FCD535) with `primaryActive` (#f0b90b) + `onPrimary` (black) — primary CTAs (black-on-yellow), active nav/filters, badges, stat numbers, wordmark; keep scarce. Trading semantics: `up`/`green` (#0ecb81), `down`/`red` (#f6465d) as **text color** for +/- values (not button fills). Shared utilities in `index.css`: `.card` (surface + hairline + 12px), `.btn`/`.btn-primary` (6px, yellow+black), `.btn-ghost`, `.tag`. Fonts: `font-sans` = Inter (copy/UI), `font-mono` = JetBrains Mono (all numbers — prices, %, stats). Flat color-block depth — no shadows/gradients/grid.

**One table everywhere** (`components/table.jsx`): `useTableControls` (search + composite/per-column filters + sort + page-size + pagination) powers declarative `DataTable({ columns, rows, rowKey, selectable, selected, onToggle, onToggleAll, ... })` — each column `{ key, label, align?, render?(row), value?(row), sortKey?, cellClass? }` where `render` = cell display, `value`/`row[key]` = what sort/filter use. **All** tables use it (16 data tables directly via controls, cadence panels / Daily-Watch movers / Product-Ads drill-down via `DataTable`), so design + filtering + sorting identical app-wide. Shared cadence column defs in `components/cadenceCols.jsx` (`bidCols` / `harvestCols(kind)` / `scaleCols` / `pauseCols` / `campaignCols` + `bidKey`/`hKey`/`cKey`/`pp`/`m2`). New tables: pass `columns` + `rows` to `DataTable`, inherit everything (incl. sticky header, since `DataTable` wraps table in `overflow-x-auto`). `DataTable` also has **`lean`** prop (+ `leanRows`, default 12): small table renders without search/filter/page-size toolbar or pagination — just compact title caption + table (sort + select-all via header still work) — auto-falls back to full toolbar + pagination once past `leanRows`. Cadence panels, Daily-Watch movers, Product-Ads drill-down pass `lean` so many short sub-tables stay clean.

**Sticky table headers** global (`index.css`, no per-component code): under `@media (hover: hover) and (pointer: fine)`, `div:has(> table)` becomes `max-height:70vh; overflow:auto` scroll box, its `thead th` = `position:sticky; top:0` with `@apply bg-panel`. So long table freezes own header while wheel scrolls it, header sticks to table (never viewport), page scrollbar still scrolls page (wheel chains out at table ends). Relies on standard `<div class="overflow-x-auto"><table>` wrapper — new tables get sticky headers free if table is direct child of its scroll div.

**Modals** (`components/Modal.jsx`): one reusable kit instead of native browser dialogs (can't theme + block thread). `<Modal>` = base portal shell (title/subtitle/body/footer, sizes `sm…2xl`, Esc + backdrop close, bg-scroll lock) for custom overlays (e.g. ProductAds ASIN drill-down). `<ModalProvider>` (mounted once in `App` around `AppShell`) exposes `useModals()` → **promise-based** `confirm` / `prompt` / `alert`, near drop-ins for `window.confirm/prompt/alert`: `await confirm({ title, message, danger, confirmLabel })` resolves bool, `await prompt({ placeholder, required })` resolves string|null, `await alert(...)` resolves void. `danger:true` styles action button red + disables backdrop-dismiss (destructive ops: delete store/audit/user, flush, clear keywords). **Never reintroduce `window.confirm/prompt/alert`** — route through `useModals()`.
